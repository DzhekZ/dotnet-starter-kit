# Module: Notifications

Per-user in-app inbox (bell icon) driven by cross-module integration events, with live SignalR push. Module `Order = 750` (**before Chat 800** so its handlers are registered before Chat publishes).

**Entities / DbContext:** `Notification` (aggregate: `UserId`, `Type`, `Title`/`Body`/`Link`, `Source`, `MetadataJson`, `ReadAtUtc`). `NotificationsDbContext`. Consumes integration events from other modules (e.g. Chat's `MentionedInChannelIntegrationEvent`).
**Areas:** List, GetUnreadCount, MarkRead, MarkAllRead. Full list: `Features/v1/` or `/scalar`.

## Gotchas

- **It's a consumer.** New notification types come from **handling another module's integration event** (`AddIntegrationEventHandlers`), not from new endpoints. The handler writes an inbox row **and** pushes `"NotificationCreated"` to SignalR group `user:{userId}` via `IHubContext<AppHub>`.
- **Order matters** — Notifications (750) must load before any publisher whose events it consumes (Chat 800). If a new module publishes events Notifications should react to, mind the `Order`.
- In-memory bus runs handlers **synchronously in the publisher's request scope** — keep the handler minimal; an exception surfaces to the originating request. See `eventing.md`.
- Inbox rows are **denormalized** (Title/Body/Link/MetadataJson copied in) so rendering never calls back into the source module. `MarkRead` is idempotent (`ReadAtUtc ??= now`).
- **Norm changes (stage 12).** `NormChangedIntegrationEventHandler` handles `NormChangedIntegrationEvent` (a norm that findings of the tenant cite was replaced or cancelled): one inbox row `norm.changed` per user in `UserIds` (the initiators of the checks, carried by the event: the platform has no "users with right X" query), Russian title and body, link `/norms/documents/{id}`, metadata with the edition, the replacement and the user's own checks; the push to `user:{id}` is best effort and never fails the handler (a retry would write every row again). The project references `Modules.Norms.Contracts` (like Chat and Billing).
- **Documents of the assistant (register AL).** `AssistantDocumentProcessedIntegrationEventHandler` handles `AssistantDocumentProcessedIntegrationEvent` (a file of a chat was parsed or failed; published by the module Assistant through the outbox after it marked the file): one inbox row for `UserId`, `Type` `assistant.document.ready` / `assistant.document.failed`, `Source = Assistant`, link `/norms?mode=files&chat={chatId}`, metadata `chatId, documentId, outcome`, Russian texts («Документ обработан» / ««файл» обработан и может быть использован в чате (n из m)», with «Все документы готовы — чат доступен» on the last one; «Не удалось обработать документ» / a hint to remove the file or retry). The tenant of the event must equal the ambient one (fail loud); the push to `user:{id}` is best effort and never fails the handler. The project references `Modules.Assistant.Contracts`; `Order` 750 < 930, so the handler is registered before the publisher. The chain Documents → Assistant → Notifications is two outbox passes, so the bell lags the end of the parse by up to ~20 s. The bell of docscheck draws the icon by `type`.
- **A missing norm came into the base (register AT, step 4).** `NormAvailableIntegrationEventHandler` handles `NormAvailableIntegrationEvent` the way the norm change is handled: a row `norm.available` for every user who started a check with findings «not in the base» about the norm (their own counts when the event names their checks, the totals of the tenant otherwise), a best-effort `NotificationCreated` push; the same guard of the tenant. Title «Норма добавлена в базу: {code}»; the body says either that the check of norm references **was started again** (`RecheckRequested`, the check is started by Checks) or asks the user to run it again; link `/norms/documents/{documentId}`, metadata `gapId`, `documentId`, `editionId`, `editionFullCode`, `findings`, `checks`, `checkIds`. The docscheck bell shows it with `FilePlus2`.
- **A role was copied into the tenants.** `RoleCopiedToTenantsIntegrationEventHandler` handles `RoleCopiedToTenantsIntegrationEvent` (Identity, through the outbox, tenant = root): one row `role.copied` for `RequestedBy`, Russian title «Копирование роли завершено», a body with the counts (created / already had it / failed, pointing to the audit trail when something failed), link `/roles/{roleId}`, metadata `roleId, roleName, created, skipped, failed`; same tenant guard and best-effort push as the other handlers. The project references `Modules.Identity.Contracts`.
